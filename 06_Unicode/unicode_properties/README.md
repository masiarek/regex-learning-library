# Naming a Unicode property: `\p{...}`

**One line:** `\p{...}` asks a question about a character — is it a **letter** (`\p{L}`), is it **Greek** (`\p{Greek}`), is it **alphabetic** (`\p{Alphabetic}`) — instead of listing the characters you hope are; the engines do not disagree about what Greek is, they disagree about how to *spell* it, and two of them accept a misspelling without a word.

**Level:** 301 · you write patterns against names, amounts and free text that are not only ASCII

**Keywords on this page:** [`\p{…}`](../../10_Keywords/unicode_property/README.md) · [`\X`](../../10_Keywords/grapheme_cluster/README.md) · [`[[:alpha:]]`](../../10_Keywords/posix_classes/README.md) · [`[…]`](../../10_Keywords/character_class/README.md) — **Topics:** [Unicode text](../../11_Topics/unicode_text/README.md)

## What it replaces

`[A-Za-z]` is a list. `\p{L}` is a question the engine answers from the Unicode Character Database it already ships. The list has 52 entries and is wrong for most of the world's names; the question is right by construction and stays right when the table is updated.

| You mean | The list you probably wrote | The property |
| --- | --- | --- |
| a letter | `[A-Za-z]` | `\p{L}` |
| a decimal digit | `[0-9]` | `\p{Nd}` |
| an uppercase letter | `[A-Z]` | `\p{Lu}` |
| punctuation | `[.,;:!?-]` | `\p{P}` |
| whitespace | `[ \t]` | `\p{White_Space}` |

The rest of this page is about which of those the engine in front of you accepts, and what it does with the ones it accepts but does not understand.

## The three things a property can name

Perl has the fullest and plainest spelling, so it is the clearest place to see all three kinds at once. Every character below is written and reported as a code point, never printed: an answer key that printed GREEK SMALL LETTER ALPHA would depend on the terminal, the locale and the runtime's build. The cast is deliberately boring — Latin, Greek, Cyrillic, Han, two digits, two spaces and a dash — because every one of those has had the same general category and the same script since the 1990s, and a key built on a character whose classification moved recently would differ between Perl 5.38 and 5.42, or between Python 3.12 and 3.14.

Four things to take from that run.

**A general category is what kind of character it is.** One letter is the union (`\p{L}` took all six letters), two letters is the subdivision (`\p{Lu}` took the three uppercase ones, `\p{Lo}` took only U+4E2D). Every character has exactly one.

**A script is what writing system it belongs to.** `\p{Greek}` took U+03B1 and U+0394 and left U+4E2D alone. A script is not "foreign" and not "non-ASCII" — U+0041 LATIN CAPITAL LETTER A is `\p{Latin}`, and so is U+00E9.

**A binary property is one yes/no fact, on a different axis from the category.** Look at the two whitespace rows: `\p{Zs}` took only U+00A0, while `\p{White_Space}` took U+0009 CHARACTER TABULATION as well. Tab's general category is `Cc`, a control character; the standard separately records that it *is* whitespace. A binary property is not a coarser category, it is a different question.

**`\P{...}` is the negation and a class composes them.** Capital `P` inverts — `\P{L}` picked up exactly the five non-letters. Inside `[...]` several properties union, and `[^\p{L}]` is the same set as `\P{L}`.

The general category rows are the only ones where everybody agrees: `\p{L}`, `\p{Lu}`, `\p{Nd}`, `\p{P}` compile in all five engines that have properties at all. Below that, three stripes:

- **The bare script name** `\p{Greek}` — Perl, Ruby and Go take it; Java and JavaScript refuse it.
- **The `Script=` form** — Perl, JavaScript and Java take it; Ruby and Go refuse it.
- **Perl's `Is` prefix** — Perl and Java take it, and no one else; PCRE2 refuses it too, which is the divergence that matters most and is measured further down.

**Binary properties are where Go stops.** `\p{Alphabetic}` and `\p{White_Space}` compile in Perl, JavaScript and Ruby, need the `Is` prefix in Java, and do not exist in Go's `regexp` at all. The last block is what Go says about them: `invalid character class range`, which does not sound like "I have never heard of that property" but is what it means, and `invalid escape sequence` for `\X`. Neither message names a property, so a reader who does not already know tends to go looking for a typo in the brackets.

The second table is the more important one, because **compiling is not understanding**:

- **Ruby accepts `\pL` and means the literal text `pL`.** It matched neither U+0041 nor U+03B1. Ruby does warn while compiling it, and the third block is that warning — captured as a flag rather than as a message, because the message carries a file name and a line number. JavaScript under `u` refuses `\pL` outright; Perl, Java and Go read it as `\p{L}`, which is what it was meant to be.
- **`\p{Alpha}` compiles in four engines and means two different things.** Perl, JavaScript and Ruby read it as the Unicode binary property `Alphabetic` and match U+03B1. Java reads it as the POSIX class over US-ASCII and does not.

### Python's `re` has no properties at all — and refuses to pretend

`bad escape \p at position 0` arrives from `re.compile`, with no subject in sight, and it is the same message on Python 3.12 and 3.14. That is the *good* outcome: a pattern lifted out of a Perl or PCRE codebase fails on the line that compiles it, not six months later on the one customer whose name is Greek. It is the same kindness Python shows for [forward references](../../01_Backreferences/forward_references/README.md).

What to reach for instead, in order of how close it stays to the original pattern:

1. **The third-party `regex` module**, which is a drop-in replacement for `re` and does have `\p{...}`. Nothing on this page uses it, because a lesson whose examples need an install is teaching something the reader's interpreter cannot do.
2. **The `str` predicates and `unicodedata`.** In the table above, `isalpha()` is True on exactly the characters whose category begins with `L`, and `isdecimal()` on exactly the two whose category is `Nd` — so they stand in for `\p{L}` and `\p{Nd}` respectively, not for the binary properties of the same name. `unicodedata.category()` hands you the two-letter category itself, which turns a general-category test into a comparison rather than a pattern.
3. **An explicit range**, which is exact when you can name the block and wrong the moment a script spills outside one. `[U+0370-U+03FF]` caught both Greek letters in the cast, and would miss every polytonic Greek letter in U+1F00..U+1FFF. **A block is not a script**; the range is a stand-in, not a translation.

`/^\p{L}$/` matched the four-character text `p{L}` and did not match U+03B1. In a legacy (non-`u`) pattern, Annex B's identity-escape rule turns `\p` into the plain letter `p`, and `{L}` is not a valid quantifier so it stays literal too. Nothing warns. A pattern written from Perl habits, tested against ASCII, passes review, ships, and quietly never matches a Greek name.

With the flag, properties are ES2018 and the rules tighten: `\pL` without braces is refused, `\p{Greek}` is refused because JavaScript wants scripts spelled `\p{Script=Greek}` or `\p{sc=Greek}`, and `\p{Alpha}` is accepted as an alias for the binary property `Alphabetic` — so it matches U+03B1, which is the exact opposite of what that same spelling means in Java.

ES2024's `v` flag adds set operations inside a class and properties of strings. This page does not probe it: the answer key has to hold on both node versions this library runs against, and `v` is not in the older one.

Java refuses `\p{Greek}` outright — `Unknown character property name {Greek}` — and wants `\p{IsGreek}`, `\p{script=Greek}` or `\p{sc=Greek}`. The same `Is` is needed for binary properties: `\p{Alphabetic}` is an error and `\p{IsAlphabetic}` is not. `\p{InGreek}` compiles too, and it is a **block** rather than a script: a block is a contiguous range of code points, a script is a property carried by each character. They agree on this cast and they part company as soon as a script spills out of its block, which is the same trap as the explicit range Python was left with above.

Then the collision this section exists for. `\p{Alpha}`, `\p{Digit}`, `\p{Upper}` and `\p{Punct}` are POSIX classes defined over **US-ASCII**. `\p{Alpha}` matched U+0041 and nothing else. `\p{Punct}` matched nothing at all, because EM DASH is not ASCII punctuation. Identical syntax to a Unicode property, a completely different meaning, no diagnostic — and a reviewer who knows Perl will read it as the Unicode one. `Pattern.UNICODE_CHARACTER_CLASS`, or inline `(?U)`, re-points all four at Unicode, and the block after it measures exactly that.

`regex` is the most complete property implementation this library measures. It is also the only engine here whose ordinary character class does **set operations**: `[\p{Greek}&&\p{Lu}]` intersected down to U+0394 alone, `[\p{L}--\p{Greek}]` subtracted the Greek letters out, and `[\p{Greek}~~\p{Lu}]` took the symmetric difference — every Greek or uppercase character that is not both. ## What it buys you

**A numeric field.** `\p{Nd}` matched U+0037 DIGIT SEVEN *and* U+0660 ARABIC-INDIC DIGIT ZERO. That is the correct reading of "a decimal digit", and it is very often not the requirement: `[0-9]` says "a digit the parser behind this field will certainly accept". They are different questions and the pattern should say which one you meant.

**A name field.** `\p{L}` took all six letters in the cast; `[A-Za-z]` would have taken U+0041 alone — not even U+00E9 LATIN SMALL LETTER E WITH ACUTE, which is Latin. A validation rule of `[A-Za-z' -]+` on a customer name does not reject foreign alphabets, it rejects accents, and the rows it rejects are the ones a support ticket gets opened about.

**`\p{Lu}` is not "uppercase".** It matched U+0041, U+0394 and U+0416 — and not U+4E2D, whose category is `Lo` because Han has no case at all. A rule that says "the first letter must be `\p{Lu}`" does not mean "capitalised" in a caseless script; it means "rejected". If what you want is "starts with a letter", `\p{L}` is the test. The same trap runs the other way for `\p{Ll}`.

## `\X`, briefly

`\X` matches one **grapheme cluster** — one character as a person counts them, however many code points that takes. U+0065 LATIN SMALL LETTER E followed by U+0301 COMBINING ACUTE ACCENT is two code points and one thing on the page: `.` matched 2 and `\X` matched 1, in Perl, in Java and in PCRE2. JavaScript, Go, Rust's `regex` and Python's `re` have no `\X`; Ruby does.

That is as far as this page goes, because "what counts as one character" is a question about text encoding rather than about patterns, and it has a library of its own: [Encodings learning library ↗](https://masiarek.github.io/encodings-learning-library/).

## The measured summary

Every cell not marked otherwise comes from a block above.

| Engine | `\p{L}` | Script spelled | Binary property | `\p{Alpha}` means | `\X` | Set ops in a class |
| --- | --- | --- | --- | --- | --- | --- |
| Perl 5.38+ | yes | `\p{Greek}`, `\p{Script=Greek}`, `\p{IsGreek}` | yes | Unicode | yes | `(?[ ... ])`, not measured here |
| PCRE2 10.48 / ABAP `PCRE` | yes | `\p{Greek}`, `\p{Script=Greek}` — **not** `Is` | yes | Unicode | yes | no |
| Java 25 | yes | `\p{IsGreek}`, `\p{sc=Greek}` — **not** `\p{Greek}` | `Is` prefix only | **US-ASCII** | yes | no |
| Ruby 3.4+ | yes | `\p{Greek}` — **not** `Script=` | yes | Unicode | yes | no |
| JavaScript, `u` flag | yes | `\p{Script=Greek}` — **not** `\p{Greek}` | yes | Unicode | no | `v` flag, not measured here |
| Go `regexp` | yes | `\p{Greek}` — **not** `Script=` | **none** | refused | no | no |
| Rust `regex` | yes | every spelling on this page | yes | Unicode | no | **yes** — `&&`, `--`, `~~` |
| Python `re` | **no** — `bad escape \p` | — | — | — | no | — |
| JavaScript, no `u` flag | **silently the literal `p{L}`** | — | — | — | — | — |

Sort those nine rows by how the failure arrives and the ordering is the useful one. Python's is a compile error you cannot miss. Go's and Java's are compile errors whose wording does not say "property". Ruby's `\pL` is a warning on a pattern that then matches nothing. And the last row does not fail at all: it compiles, it runs, and it matches the wrong thing for as long as nobody types a non-ASCII letter into the field.
