# Escaping and literal text

**One line:** Fourteen characters have a meaning in a pattern and need a backslash to be themselves — the same fourteen in every engine here — and the rest of the story is what a backslash before an *ordinary* letter does, which is the part the engines disagree about: an error in Python, Java, Go and Rust, and the letter itself in Perl, JavaScript and Ruby.

**Level:** 201 · you are building a pattern from text you did not write

## The characters

| Needs escaping outside a class | `\` `^` `$` `.` <code>&#124;</code> `?` `*` `+` `(` `)` `[` `]` `{` `}` |
| --- | --- |
| Needs escaping inside a class | `\` `]` and, by position, `^` `-` (see [character class](../../10_Keywords/character_class/README.md)) |
| Never needs escaping | `/` — a delimiter in Perl, JavaScript and Ruby *literals*, not a metacharacter; `-` outside a class; `,` `:` `;` `=` `!` `<` `>` `@` `#` (except under `(?x)`) |

Escaping `{` and `}` is the one that varies: an unmatched `{` is a literal in six engines and an error in Java and Rust, so the backslash is the portable spelling.

### Reading the table

- **Rows 1–3.** `a.b` matches `axb`; `a\.b` and `a[.]b` do not. All eight agree, and both escaped spellings are equally portable — the class is the one that survives being pasted into a shell, where a backslash may be eaten first.
- **Rows 4–9** are unanimous too: escaped `*`, `[`, `]`, `{`, `}`, `\` are literals, and `-` and `/` were never special outside a class.
- **Row 10, `\e`.** An escape sequence for ESC (U+001B) in Perl, Ruby, Java and `fancy-regex`. Refused by Python, Go and Rust's `regex`. **JavaScript matched nothing**: `\e` is the letter `e` there, and the subject held no `e`.
- **Row 11, `\q`.** A letter with no meaning behind a backslash. **Perl, JavaScript and Ruby read it as `q`** and matched. Python, Java, Go and Rust refuse. This is the row that decides how safe an escaping function has to be: in the first three engines, over-escaping is harmless; in the other four, backslashing the wrong letter is a compile error. (Python reserves *every* `\` + ASCII letter as an error unless it is defined, since 3.7.)

Python, Perl and Ruby escape the space; Go and Rust do not; Java escapes nothing and wraps the text in `\Q…\E`. Each output is correct *for its own engine* — and a Python-escaped string handed to Java contains `\ `, which Java refuses as an unknown escape. **Escape in the language that will run the pattern**, never upstream of it.

## The rules

1. **Text from outside the program is escaped before it becomes part of a pattern**, with the language's function: `re.escape`, `quotemeta`, `Regexp.escape`, `Pattern.quote`, `regexp.QuoteMeta`, `regex::escape`. JavaScript's `RegExp.escape` arrived in ES2025; before that, `s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")` is the idiom.
2. **A replacement string from outside is escaped too**, against a *different* set — `$` and `\` — because the replacement is its own [language](../../10_Keywords/replacement_references/README.md). Or use a function as the replacement, which needs no escaping at all.
3. **Prefer a class to a backslash** where both work: `[.]` and `[$]` survive shell quoting, YAML, and a second round of escaping better than `\.` and `\$`.
