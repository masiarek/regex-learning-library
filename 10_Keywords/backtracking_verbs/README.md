# `(*SKIP)`, `(*FAIL)`, `(*COMMIT)`, `(*PRUNE)`, `(*ACCEPT)` — steering the backtracker by hand

**One line:** The backtracking control verbs tell a Perl or PCRE2 engine what to do when a match fails past this point — give up entirely, skip ahead, refuse to retry the alternative, or stop matching early and call it a success — and they exist in Perl and PCRE2 (so ABAP) and nowhere else on this page.

**Level:** reference · the most Perl-specific page in the library

## What it means

| Verb | On backtracking past it | The job it does |
| --- | --- | --- |
| `(*FAIL)` or `(*F)` | fails immediately | an alternative that can never succeed — used with `(*SKIP)` |
| `(*SKIP)` | the next attempt starts *after* the text matched so far, not one character on | "match this, then throw it away and continue from after it" |
| `(*PRUNE)` | the current starting position is abandoned; the engine advances one character | "no retries from here, try the next offset" |
| `(*COMMIT)` | the whole match fails; no other starting position is tried | "if this fails, everything fails" |
| `(*ACCEPT)` | none — the match ends here, successfully, with what has been consumed | early exit with a partial match |

The idiom that pays for the whole table is `X(*SKIP)(*F)|Y`: match `X`, discard it, and never let `Y` match inside something that `X` matched. It is how you find every comma that is *not* inside quotes with one pattern.

### Reading the table

- **Rows 1–2, the `(*SKIP)(*F)` idiom.** Replacing the first match of `"[^"]*"(*SKIP)(*F)|,` with `X` in `"a,b",c` gives **`"a,b"Xc`** — the comma inside the quotes was skipped over, the one outside was replaced. Without the verbs, the same alternation's first match is the quoted string itself, and the result is `X,c`. Perl alone; every other engine refuses the verbs.
- **Rows 3–4, `(*COMMIT)`.** `a(*COMMIT)b|ac` on `ac`: `a` matches, `(*COMMIT)` is passed, `b` fails — and the whole match fails, without trying the `ac` alternative that would have worked. Without the verb, `ac`.
- **Row 5, `(*PRUNE)`.** `a+(*PRUNE)ab` on `aab`: `a+` takes both `a`s, the verb is passed, `ab` fails; without the verb the engine would give one `a` back and match `aab`. With it, backtracking into `a+` is forbidden, the attempt at offset 0 is abandoned, and no later offset works either. Row 6 is the same pattern without the verb, matching.
- **Row 7, `(*ACCEPT)`.** `a(*ACCEPT)b` on `ac` matches `a` — the pattern says `b` must follow, and `(*ACCEPT)` says stop here anyway.

## The trap

Portability is not the trap; the verbs refuse to compile anywhere else, which is honest. The trap is reasoning about them. `(*PRUNE)` and `(*COMMIT)` are about where the engine goes *after* a failure, and the mental model needed is the backtracker's, not the pattern's. Where a `(*SKIP)(*F)` pattern can be replaced by matching the quoted strings *and* the commas in one alternation and deciding in the host language which was which, the second version is the one the next reader will understand.

Where they earn their keep: `pcre2grep`, `grep -P`, and ABAP — places where the pattern is the whole program and there is no host language to decide in.
