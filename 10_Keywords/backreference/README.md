# `\1` — match the text group 1 matched

**One line:** A backreference re-matches the *text* a group captured, not its pattern; it exists in every engine here except Go and Rust's `regex`, which refuse it in exchange for a linear-time guarantee; and the edges — an unset group, a reference written before its group, `\10` with one group — are where the six that have it stop agreeing.

**Level:** reference · one construct, eight engines — [chapter 01](../../01_Backreferences/README.md) has the depth

## What it means

`(a)\1` matches `aa`. `(\w+) \1` matches a doubled word. The reference is to whatever the group *captured this time*, which is why `(\d\d)-\1` matches `12-12` and not `12-34` — matching the *pattern* again is a [subroutine call](../recursion_and_subroutine_calls/README.md), a different feature.

| Spelling | Refers to | Accepted by |
| --- | --- | --- |
| `\1` … `\9` | group by number | all six engines that have backreferences |
| `\g{1}`, `\g1` | group by number, unambiguously | Perl, PCRE2 |
| `\g{-1}` | the group *before* this point, relative | Perl, PCRE2 |
| `\k<1>` | group by number in the named syntax | Ruby, `fancy-regex` |
| `\k<name>`, `(?P=name)` | group by name — the [named group](../named_group/README.md) page | varies |

### Reading the table

- **Row 1** is the feature: `(a)\1` finds `aa` in six engines. Go and Rust's `regex` refuse — a compile error, which is the honest way to not have a feature.
- **Row 2, the unset group.** `(a)?b\1` on `b`: group 1 never matched. Five engines say a reference to an unset group fails. **JavaScript says it matches the empty string** and returns `b`. This one rule is behind the [forward references](../../01_Backreferences/forward_references/README.md) finding, where JavaScript accepts subjects nobody else does.
- **Row 3, a reference before its group.** `(?:\1x|(a))+` compiles in Perl, JavaScript, Ruby, Java and `fancy-regex`, and **Python refuses it at compile time** — the chapter's biggest portability cliff.
- **Rows 4–5, `\g{1}` and `\g{-1}`.** Perl alone. JavaScript and Ruby compile them and match nothing, because `\g` is the letter g there. Python, Java, `fancy-regex` refuse.
- **Row 6, `\k<1>`.** Ruby and `fancy-regex` accept a number in the named-reference syntax; JavaScript compiles it as `k<1>` and matches nothing.
- **Row 7, `\10` with one group.** There is no group 10, so what is `\10`? **Perl, JavaScript, Ruby and Go read it as octal** — U+0008, a backspace — and matched `a` followed by one. Java read it as group 1 followed by a literal `0` and found none. Python refused. `fancy-regex` refused. Five answers, one two-character escape.
- **Row 8, `(?i)(a)\1` on `aA`.** Six engines fold the backreference comparison too. Whether they fold *non-ASCII* the same way is the [case-insensitive lesson's](../../06_Unicode/case_insensitive_matching/README.md) last table.

## The trap

Rows 2 and 3, which are the same trap from two sides: a pattern that means one thing in Perl and is either an error (Python) or a *different pattern* (JavaScript) elsewhere. The general rule is that a backreference is the feature most likely to be accepted with a changed meaning, because so much of its behaviour is defined at the edges.

And row 1's `-` cells are not a gap. A backreference makes the match problem NP-hard in general; [what a backreference costs](../../01_Backreferences/what_a_backreference_costs/README.md) is the measurement, and the Go and Rust answer — match two groups, compare in the host language — is linear and readable.
